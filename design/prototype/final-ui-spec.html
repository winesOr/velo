Velo 最终 UI 原型基准 V1

本文件把原型变成后续真实 UI 改造的逐项验收基准：详情评分回到海报信息组，剧集连续滑动并自动同步分组，音频与字幕采用当前 Velo 的双行选择字段，通知与弹窗统一为顶部轻通知、居中对话框和锚定菜单；播放界面内的面板例外，统一为右侧抽屉。任何弹窗与提示都不从底部滑出。

修订：FINAL-UI-V1 · 本轮定稿。范围为七个 HTML 页面（一个总览、六个产品页）；不改 Flutter、Android 或播放器核心。当前真实样式依据源码核查，未声称与真机逐像素一致。

1. 基准如何使用

先按页面入口复现指定状态，再按组件编号检查布局、颜色、文字、交互和焦点，最后在相同尺寸/主题下比较截图。下方勾选项用于未来真实 Velo UI 改造验收，默认未勾选不代表 HTML 原型尚未实现。HTML 中勾选仅保存在当前浏览器；不是代码实现状态或测试报告。

优先级：本轮用户明确要求 → 本规范与定稿原型 → 早期研究文档。旧的详情海报外评分区、底部提示、按钮堆式轨道列表不再是目标。原型状态演示与服务端接口分离；不得把演示按钮、计时器、虚构媒体数据带入生产流程。

8. 默认值、数据与研究边界

  • 详情评分、轨道、房间、线路均为显式本地mock。评分主界面仅icon+数值；未知来源在说明弹窗和aria-label保持“服务器评分/来源未标注”，不猜TMDB；APK的IMDb/RT/Trakt资源不等于已确认HTTP调用。多个评分不等于多个独立请求。
  • 首页加载时序600/1000/1700/5000/700/900ms仅为设计演示。Velo已多服渐进；身份就绪后的共享2秒内容预算不是启动总时长。新的逐库和缓存方案仍需真实实现与测量。
  • 缓存偏好初始unset、容量/时长空、硬解跟随核心；资源中的512MB不是VidHub运行默认。最快线路算法、真实缓存命中与评分上游仍未知。
  • 音轨切换pending/失败为本地交互状态，不代表mpv或ExoPlayer实测；源ID与native ID的区分须在真实实现保留。未支持的次字幕能力不得伪装可选。
  • 主题模式保留system/light/dark；邀请码246810仅演示。没有新增服务器、账号、私密URL、内置网关或第三方密钥。
