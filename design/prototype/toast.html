提示条 · 定稿（方案 A）

SHARED-03 定稿：顶部居中磨砂胶囊。已替换原型所有页面的 UI.toast（首页、搜索、详情、一起看、设置、播放器共用 toast.js / toast.css），实机将用同一规格替换底部 SnackBar。按钮会同时在手机竖屏、横屏播放器、TV 三个画面里触发；用上方“浅色 / 深色”切换外观。方案 B、C 保留在页面下方的“未采用方案”中备查。

设计说明 · 现在的提示条为什么难看

  1. 位置打架。实机是 SnackBarBehavior.floating + insetPadding 16，落在底部，正好叠在 58px 悬浮胶囊导航上方，两个浮层上下挤在一起；播放器里则压在进度条和底栏上。原型顶部版 top:52px 又正好盖住“设置”大标题和返回行。
  2. 体量过重。手机上不限宽（左右各 16），内边距 16×14、图标 22、圆角 18，一句“已收藏”也是一整条通栏卡片，比它反馈的操作更抢眼；最大高度 30% 屏还能内部滚动。
  3. 颜色与品牌脱节。成功用 Material 绿 #88D8B0 / #216B4B，错误用 colorScheme.error，提示用 primary；三种颜色只出现在图标上，和 Velo 的中性底 + 紫色焦点没有关系。原型版则完全没有状态图标，成功 / 错误长得一样。
  4. 深色下像一块实心按钮。#202020f2 + 1px 描边，在 #121212 页面上几乎没有层次差，又不够透，看起来像可点的按钮而不是浮层。
  5. 连续触发会排队。ScaffoldMessenger.showSnackBar 默认排队，连点 3 次要等 3 × 3s 才消失（只有 showMainSnackBar 会先 remove）；原型则每次 remove 再重建，反复闪入场动画。没有“×3”合并。
  6. 没有操作和加载态。helper 不支持 action（全仓 SnackBarAction 0 处），撤销 / 重试只能另做；也没有 loading → 完成的衔接，收藏按钮的加载态和提示是两套东西。
  7. 交互不一致。只有桌面能点击关闭，手机不能上滑关闭；悬停不暂停；原型版 pointer-events:none 完全不能交互；错误与普通提示在读屏上同一等级。

可调参数

修改后对下一次触发生效。悬停、按住或键盘焦点在提示条内时计时暂停。

定稿 · 方案 A 顶部居中磨砂胶囊

FINAL · 已选

与底部悬浮导航同一套语言：44px 高、全圆角、26px 磨砂 + 0.5px 描边，只用 18px 状态图标着色，文字始终中性色。短句时只有内容宽度，两行时自然变成圆角矩形。带操作（撤销 / 重试）或错误时，胶囊底部有一条 2px 剩余时间细线（借自方案 B）。播放器内始终深色材质。连续相同提示原地 ×N，不同提示原地换内容；手机上落在顶栏下方，不遮账号 / 搜索等顶栏操作；TV 上放到右上标题安全区、导航下方，不获取焦点，操作改为“按菜单键”执行。

定稿行为规范（与 final-ui-spec SHARED-03 一致）

外观

  • 胶囊：最小高 44、内边距 11 / 18（左 14）、圆角 22（两行时仍 22，成为圆角矩形）、最大宽 = 屏宽 − 32，横屏 460，TV 720
  • 材质：深色 rgba(34,34,36,.66) / 浅色 rgba(253,252,249,.72)，blur 26 + saturate 1.4，0.5px 描边 #ffffff1f / #2424241c，阴影 0 10 32
  • 文字：14 / 20、500，中性正文色，最多两行省略；TV 28 / 38
  • 状态图标 18px（TV 34）：成功 #86d8ae / #1f7a50、提示 --velo-focus、错误 #ff8f86 / #c23a31、加载中为转圈（说明文字色）
  • 操作：行内文字按钮 28 高、圆角 14，品牌淡紫；剩余时间细线 2px，距左右 18、底 3，仅带操作或错误时显示
  • 播放器内（包括浅色模式）始终使用深色材质

时长、合并与动画

  • 成功 / 提示 2.5s，错误 4s，带操作（撤销 / 重试）5s，TV 另加 1s；加载中不自动消失
  • 悬停 / 按住 / 焦点在内时暂停计时
  • 全局单槽位，永不堆叠。相同文案 + 同类型：原地 ×N 并重置计时；不同文案：原地淡出旧内容、淡入新内容（120ms）
  • 加载：先显示按钮内联忙碌态，超过 300ms 才出“正在…”提示条，完成后原地变为成功 / 错误（错误带“重试”）
  • 入场 220ms（上移 10px + 缩放 .94 → 1 + 淡入），出场 180ms，缓动 cubic-bezier(.2,.8,.2,1)；减少动态时为 150ms 淡入、120ms 淡出
  • 关闭：点击提示条、向上滑 ≥18px、焦点在内时按 Esc；点操作后由新结果原地替换

位置与无障碍

  • 手机竖屏：水平居中，页面顶栏下方 8（首页 = 94）；无顶栏时为状态栏下 8（= 50）。不遮顶栏操作
  • 横屏播放器：顶栏 HUD 可见时放在 HUD 下方 8，HUD 隐藏后上移到 14；左右避开 44 安全区；随 HUD 显隐实时跟随
  • TV（1920×1080 坐标）：右上角，距右 96（5% 标题安全区），顶部导航下方 16（无导航时上 54）；不获取焦点，操作显示为“菜单 撤销”，按遥控器菜单键执行
  • 页面常驻 role=status（polite）与 role=alert（错误）两个 live 区域；触发时不移动焦点，手机操作按钮可用 Tab 到达
未采用方案 · B 紧凑卡片 / C 灵动岛（展开查看，按钮仍可演示）

B 未采用：通栏卡片覆盖面积最大，显示期间盖住页面顶栏操作，与 SHARED-03“不遮关键顶栏操作”冲突；左侧色条偏工具化。其剩余时间细线已并入 A。
C 未采用：浅色模式下是一块黑色；播放器 HUD 可见时只能离开“岛”位置，比喻失效；TV 需要让顶部导航让位；尺寸测量 + 形变实现成本最高，Android 实机也没有对应的硬件岛。

方案 B · 贴安全区紧凑卡片 + 左侧状态色条

CLEAR

状态栏下方 4px、左右 10px 的通栏卡片，14px 圆角，左侧 4px 状态色条一眼区分成功 / 提示 / 错误；带操作和错误时底部有一条剩余时间细线。从顶部滑入、向上收回。信息最清楚，操作按钮最好点，但覆盖面积最大，显示期间会盖住页面顶栏操作（与 SHARED-03“不遮关键顶栏操作”有冲突，需页面配合）。

方案 C · 灵动岛式从顶部展开

PLAYFUL

近黑胶囊从状态栏中央的“岛”位置长出：加载时是紧凑小岛（转圈 + 短字），完成后原地展开成结果；连续触发时轻弹并计数。形变本身就是反馈，最有记忆点；但浅色模式下是一块黑色，TV 顶部需要让导航暂时淡出，Android 实机也没有对应的硬件岛。

A · 磨砂胶囊已选最安静；与底部导航胶囊同一语言，海报透出最多中：一行短句 + 图标；两行时变圆角矩形，操作是行内文字按钮好：体积小，HUD 下方居中，几乎不挡画面好：右上安全区，28px 可读，避开导航低：单个 OverlayEntry + AnimatedSwitcher / AnimatedSize，BackdropFilter

已选 A（2026-11-15 用户确认）。它最符合 Velo“安静、海报优先、磨砂浮层”：与底部悬浮导航同材质同圆角，成为一套上下呼应的浮层；体积只取决于文字，海报和播放画面被遮挡最少；横屏和 TV 的位置规则最简单。实现成本最低，可直接替换 snackbar_helper.dart 的入口而保持调用签名。同时采纳：从 B 借用剩余时间细线（带操作 / 错误时显示）；TV 不抢焦点，撤销 / 重试提示“按菜单键”执行；播放器内在浅色模式下也保持深色。
