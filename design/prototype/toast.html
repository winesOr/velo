提示条 · 三个方案待选

全局统一替换实机底部 SnackBar 的候选方案。三个方案共用同一套行为（单槽位、替换 / 合并不堆叠、按类型停留、可点击或上滑关闭、不抢焦点），只在视觉、位置与形变方式上不同。每个方案的按钮会同时在手机竖屏、横屏播放器、TV 三个画面里触发；用上方“浅色 / 深色”切换外观。选定前，其他原型页面的提示条保持原样，final-ui-spec 不改。

设计说明 · 现在的提示条为什么难看

  1. 位置打架。实机是 SnackBarBehavior.floating + insetPadding 16，落在底部，正好叠在 58px 悬浮胶囊导航上方，两个浮层上下挤在一起；播放器里则压在进度条和底栏上。原型顶部版 top:52px 又正好盖住“设置”大标题和返回行。
  2. 体量过重。手机上不限宽（左右各 16），内边距 16×14、图标 22、圆角 18，一句“已收藏”也是一整条通栏卡片，比它反馈的操作更抢眼；最大高度 30% 屏还能内部滚动。
  3. 颜色与品牌脱节。成功用 Material 绿 #88D8B0 / #216B4B，错误用 colorScheme.error，提示用 primary；三种颜色只出现在图标上，和 Velo 的中性底 + 紫色焦点没有关系。原型版则完全没有状态图标，成功 / 错误长得一样。
  4. 深色下像一块实心按钮。#202020f2 + 1px 描边，在 #121212 页面上几乎没有层次差，又不够透，看起来像可点的按钮而不是浮层。
  5. 连续触发会排队。ScaffoldMessenger.showSnackBar 默认排队，连点 3 次要等 3 × 3s 才消失（只有 showMainSnackBar 会先 remove）；原型则每次 remove 再重建，反复闪入场动画。没有“×3”合并。
  6. 没有操作和加载态。helper 不支持 action（全仓 SnackBarAction 0 处），撤销 / 重试只能另做；也没有 loading → 完成的衔接，收藏按钮的加载态和提示是两套东西。
  7. 交互不一致。只有桌面能点击关闭，手机不能上滑关闭；悬停不暂停；原型版 pointer-events:none 完全不能交互；错误与普通提示在读屏上同一等级。

可调参数

修改后对下一次触发生效。悬停、按住或键盘焦点在提示条内时计时暂停。

方案 A · 顶部居中磨砂胶囊

QUIET

与底部悬浮导航同一套语言：44px 高、全圆角、26px 磨砂 + 0.5px 描边，只用 18px 状态图标着色，文字始终中性色。短句时只有内容宽度，两行时自然变成圆角矩形。连续相同提示原地 ×N，不同提示原地换内容；手机上落在顶栏下方，不遮账号 / 搜索等顶栏操作；TV 上放到右上标题安全区、导航下方。

方案 B · 贴安全区紧凑卡片 + 左侧状态色条

CLEAR

状态栏下方 4px、左右 10px 的通栏卡片，14px 圆角，左侧 4px 状态色条一眼区分成功 / 提示 / 错误；带操作和错误时底部有一条剩余时间细线。从顶部滑入、向上收回。信息最清楚，操作按钮最好点，但覆盖面积最大，显示期间会盖住页面顶栏操作（与 SHARED-03“不遮关键顶栏操作”有冲突，需页面配合）。

方案 C · 灵动岛式从顶部展开

PLAYFUL

近黑胶囊从状态栏中央的“岛”位置长出：加载时是紧凑小岛（转圈 + 短字），完成后原地展开成结果；连续触发时轻弹并计数。形变本身就是反馈，最有记忆点；但浅色模式下是一块黑色，TV 顶部需要让导航暂时淡出，Android 实机也没有对应的硬件岛。

共用行为规范（三个方案一致）

类型与停留

  • 成功 2.5s · 对勾 · role=status
  • 提示 2.5s · 信息图标 · role=status
  • 错误 4s · 感叹号 · role=alert；可带“重试”
  • 带操作（撤销 / 重试）5s，不论类型
  • 加载中 不自动消失；先显示按钮内联忙碌态，超过 300ms 才出提示条，完成后原地变为成功 / 错误（不重新入场）
  • TV 上述时长 +1s；悬停 / 按住 / 焦点在内时暂停计时
  • 文本最多两行，超出省略；完整内容保留在无障碍文本和 title 中

连续触发与动画

  • 全局单槽位，永不堆叠。相同文案 + 同类型：原地计数 ×N 并重置计时；不同文案：原地淡出旧内容、淡入新内容（120ms）
  • 入场 220ms（C 形变 240ms），出场 180ms，均 ≤240ms，缓动 cubic-bezier(.2,.8,.2,1)
  • 减少动态：所有位移 / 缩放 / 形变改为 150ms 淡入、120ms 淡出
  • 关闭：点击提示条、向上滑 18px 以上、焦点在内时按 Esc；点操作按钮执行后由新结果替换

无障碍与位置

  • 页面常驻两个 live 区域（status / alert），提示条插入其中被朗读；触发时不移动焦点，操作按钮可用 Tab 到达
  • 手机竖屏：A 放在页面顶栏下方 8（首页 = 94；无顶栏的页面为状态栏下 8 = 50），不遮顶栏操作；B 贴状态栏下 4（46）、左右 10，会暂时盖住顶栏；C 顶部 4，在状态栏中央展开
  • 横屏播放器：顶栏 HUD 可见时放在 HUD 下方（≈ 60），HUD 隐藏后上移到 8–14；左右避开 44 安全区；始终使用深色材质
  • TV：1920×1080 坐标，标题安全区 5%（右 96）；正文 28px、图标 34–36px；A / B 放右上、顶部导航下方（上 150），不与导航重叠；C 居中并让导航暂时淡出。不获取焦点，操作改为遥控器菜单键提示

方案对比

视觉信息密度播放器内表现TV 表现实现复杂度（Flutter）
A · 磨砂胶囊推荐最安静；与底部导航胶囊同一语言，海报透出最多中：一行短句 + 图标；两行时变圆角矩形，操作是行内文字按钮好：体积小，HUD 下方居中，几乎不挡画面好：右上安全区，28px 可读，避开导航低：单个 OverlayEntry + AnimatedSwitcher / AnimatedSize，BackdropFilter
B · 紧凑卡片清晰但更“工具化”；色条略抢眼高：长文本、操作按钮、剩余时间线最从容中：通栏会盖住更多画面，需限宽 440最好：右上卡片，状态色条远距离也易辨认低：同 A，多一个计时进度
C · 灵动岛最有记忆点；浅色模式下黑块突兀中：加载紧凑态很好，长文本时岛变得很大差：HUD 可见时只能离开“岛”位置，比喻失效差：与顶部导航抢位置，需让导航淡出高：尺寸测量 + 宽高 / 圆角联动形变，各平台安全区与刘海差异多

推荐 A。它最符合 Velo“安静、海报优先、磨砂浮层”：与底部悬浮导航同材质同圆角，成为一套上下呼应的浮层；体积只取决于文字，海报和播放画面被遮挡最少；横屏和 TV 的位置规则最简单。实现成本最低，可直接替换 snackbar_helper.dart 的入口而保持调用签名。可以从 B 借一条：带操作 / 错误的提示可选显示剩余时间细线。
