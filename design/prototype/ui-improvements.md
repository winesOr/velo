## 2. UI-01 · 首页从整页等待变为按区块可用

**来源：** 用户首页截图的全幅海报、横向继续观看卡片、媒体分类行与悬浮导航；Velo 同服 Latest 等待全部 worker 的代码观察。**研究推演：** 按库显示与保旧是一项优化建议，不能据 VidHub 方法日志声称已还原其渲染机制。

**方案：** 维持 hero 轮播、海报取色与既有卡片比例；单个区块的数据未到就使用固定尺寸占位，已到内容立即可点击。装饰性评分后补不移动卡片和焦点。正常进入默认可用页面，不强制让每位评审等待演示流程。

**交互入口：** 首页外部“启动演示”工具的五个按钮切换正常、缓存、首次、慢库和部分失败；工程说明留在工具区，不把 APK 研究术语放进产品内容。所有到达顺序只代表设计意图。

**验收：** 慢行不阻挡已完成行；首次加载没有假的评分或可点击空卡；快速换场景/服务器不串入旧结果；深浅主题均能辨识占位和内容；轮播快速连点不出现过时背景。关联 PERF-02 / 03 / 05 / 06。

## 3. UI-02 · 评分可解释，缺失不伪装成 0 分

**来源：** 用户确认首页轮播与角标有分数，但 VidHub 实际字段和站点来源未知。APK 的 IMDb / RT / Trakt 标签只证明有对应资源；服务端徽标不等于评分提供方。

**方案：** 轮播和海报保留简洁单项评分并提供说明入口；主界面只显示图标和分数，平台/类型/示例名称不单列；明确来源和尺度、未确定的“评分 / 来源未标注”放在点击说明与无障碍标签中。分数尚未到达时保持缺失或占位，不写 0.0；补到后原位更新。服务器归属和评分来源分开呈现。

**交互入口：** 首页 hero 评分按钮、电影行“评分来源说明”，以及详情 hero 信息组内紧凑评分条的居中说明弹窗。演示中的标签只说明本地样例，不意味着真的调用对应站点。当前 Velo 海报最多 1 项、详情最多 4 项是展示策略，不是竞品还原事实。

**验收：** 未知来源不被自动命名 TMDB / IMDb；10 分制与百分比不混写；说明可由键盘打开并关闭；缺分、后补、来源说明分别可评审；不得为了展示多个品牌发真实外部请求。关联 PERF-08。

## 4. UI-03 · 详情先支持行动，再展开信息

**保留：** 海报与渐变背景、主要播放动作、收藏/已看、剧集/版本、演职员与信息区；海报取色与玻璃浮层沿用现有系统。用户截图中完整演员、类型、音视频信息及文件信息是设计参照，不能声称本轮新增了全部真实字段。

**本轮方案：** 评分提供来源说明；当前可用条目不等待额外评分或 Logo。详情浮层统一为现代居中 dialog；通知统一顶部轻提示，不允许从底部弹出。信息缺失时使用中性状态，不用截图内作品的数据冒充真实服务器响应。

**验收：** 详情入口和已有收藏/已看、版本/剧集交互不回退；浮层 Escape 关闭并回到发起按钮；原有主操作可用；多个评分不意味着多站网络请求。关联 PERF-03 / 08。真实元数据获取与音视频探测仍未实现于本轮。

## 5. UI-04 · 设置分清网络、首页缓存与播放缓冲

**来源：** VidHub 主线路/自动最快/手动备份资源、缓存到磁盘与容量/时长资源、硬解等选项；最新证据没有确认最快线路算法或运行时默认值。名称必填和端口 1–65535 依据资源提示，本轮仅实现格式交互。

**方案：** 在设置增加“网络与缓存”分类，分为线路、首页内容缓存、图片缓存、播放缓冲；播放硬解保留“未设置 / 跟随核心”语义。新值以未设置开始，不把资源文本 512 MB 作为真实默认或上限。保留 mpv / ExoPlayer；VLC 仍标为可选计划。

**交互入口：** 手机设置首页或 TV 侧栏 → 网络与缓存；线路新增/选择/删除与名称、地址、端口表单；首页/图片/播放项分别解释作用，容量与时长可以留空。播放 → 硬件解码 →“查看偏好”可查看跟随核心状态。保存仅修改本地原型偏好，既不修改手机设置也不执行网络操作；测速不得显示伪造的延迟排名。

**验收：** 空名称、端口 0 / 65536 / 非数字被拒绝；合法格式可保存且重新打开一致；取消不保存；不收集密码或令牌；未设置值保持未设置语义；不能宣称选择“自动最快”已完成测速。关联 PERF-05 / 06 / 07 / 09。

## 6. UI-05 · 保留旧内容，局部失败可恢复

**研究推演：** “旧数据仍可用”比整页消失更适合缓存刷新；其正式实现必须先满足身份、权限、隐藏库和 session epoch。原型只展示已授权样例，不提供授权保障。

**方案：** 有缓存时保留当前卡片，更新提示不遮住内容；无缓存时显示行级占位；失败只影响该行并提供重试，其他行继续操作。重试针对单行，不刷新整个首页；场景切换取消旧演示任务，不让迟到结果覆盖当前状态。

**验收：** 缓存刷新失败不会清空全部内容；失败位置、重试入口和当前可用内容能够同时辨认；重试不打断其他行；新旧数据更新保留阅读位置。真实离线/撤权/注销处理另按 PERF-05 验证。

## 7. UI-06 · 手机与 TV 保持同一套可达交互

**保留基线：** 原型既有手机、桌面和 TV 示例、方向键/Enter 导航、统一 dialog 的 Tab 约束与 Escape 关闭/焦点返回；system / light / dark 三外观与已有跨页状态同步。

**方案：** 新评分入口、场景选择、失败重试、线路表单与设置项使用可聚焦按钮；异步补全不自动夺取焦点；固定卡片尺寸避免遥控器焦点位置漂移。文档本身响应式，可键盘访问、打印，并响应系统深浅色与减少动态设置。

**验收：** 手机 390 宽可操作且无关键内容被遮；TV 方向键和 Enter 可到达新增控件；弹窗 Tab 不漏出、Escape 返回原焦点；深浅主题文字对比可读；减少动态模式不阻止功能。当前为浏览器验收要求，不能替代实体遥控器和 Android 无障碍测试。

## 8. UI-07 · 保留既有能力与产品边界

- 一起看继续保留创建、加入、准备与邀请演示；邀请码 `246810` 为原有演示值，不是真实房间。新增启动状态不能破坏会话入口。
- 媒体库保留搜索、多筛选、排序、无结果与重置；演示数据范围沿用现有原型，不改为真实服务器数据。
- 投屏入口只在播放器；首页与设置不新增投屏按钮。真实投屏未在本轮接入。
- 保留 Plex、Jellyfin、Emby 与手机/TV 的产品方向；保留 mpv/ExoPlayer；弹幕网关仍由用户配置，初始源为空，不内置密钥或服务地址。

**验收：** 以上已有流程分别冒烟回归，不因本轮首页与设置改动失效。它们属于保留能力，不能写成此次新实现的完整功能。

## 12. FINAL-UI-V1 定稿增补

- 详情评分回到海报 hero 的元信息之后、播放之前；去掉独立研究评分区，缺分整条收起。主界面仅icon+分数，来源和mock说明在点击弹窗与aria-label保留。
- 剧集采用连续横向列表：跨第10/11集自然衔接，分组跟随可见剧集，反向同步；点分组跳至该组，换季重置。精确规则与验收见DETAIL-04。

- 状态演示包含无音轨、次字幕能力限制、切换中、失败回滚；全为本地模拟，不能写成原生播放器已修改。
