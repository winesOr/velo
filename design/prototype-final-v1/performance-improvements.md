# 性能优化功能点

**UI 定稿入口：** [最终 UI 原型基准 V1](final-ui-spec.html)。性能方案与测量保持本文件独立记录；HTML 原型更新不等于生产提速。

优先缩短“身份已确认之后，首页第一批可用内容到达”的时间：把同一服务器里的媒体库分批发布，让评分、Logo 和剧集补全退出首屏等待链。Velo 已经按服务器渐进发布，Continue 与 Hubs 已并行；本轮建议是在现有机制上缩短等待范围。没有同环境对照测试，不能宣称已经提速，也不能将原型定时器当作生产性能。

本轮交付是早期 V3 系列 HTML 原型的设计升级及实施清单。**原型可演示不等于 Dart / native 已实现。** 首页缓存、线路、评分均为本地样例；实际服务端访问、缓存策略与硬解参数未在本轮修改。

## 1. 证据与当前基线

| 观察 | 已有证据 | 能说明什么 / 不能说明什么 |
| --- | --- | --- |
| VidHub 进程冷启 | 一次 Activity TotalTime 995 ms，保留磁盘数据 | Activity 启动耗时；不是海报可见耗时 |
| VidHub 暖返 | 一次同 task 置前 166 ms | 已有任务回前台；不能与进程冷启直接比较 |
| VidHub 首页 ready | loading_hidden 133 ms；all_enabled_sections_ready 135 ms；对应 itemCount 均为 0 | 空状态日志；不能称 135 ms 资源完整或缓存首显 |
| VidHub 首页资源方法 | getMediaViews 1120 ms；getResumeItems 272 ms；5 个 Latest 在约 3 ms 窗口发起，成功回调位于首页起点后约 2108–2168 ms | 方法级时序；不证明 socket 并发、首图、逐库渲染或最快线路算法 |

| Velo 本地快照 | 授权 scope / epoch / 隐藏库约束；仅 online 客户端读；24 小时 TTL | 已有缓存机制；放宽读取门槛需要重新证明权限安全 |

## 2. P0：先建立可比较的首页指标

### PERF-01 · 分开测启动、资源和视觉就绪

**问题：** Activity、空模型 ready、网络成功与海报显示不是同一终点；现有单次 VidHub 观测无法支持“快多少”。

**方案：** 为一次首页会话分配不含用户信息的 trace ID，关联 identity、online、snapshot、Views、Resume、NextUp、Latest、图片请求与 UI 提交；分别记录方法级和 HTTP 级时序，避免把并发方法调用误认为网络连接并发。

**代码定位：** `<local-path-withheld>`、`:2276`；`lib/navigation/profile_session_screen.dart:249`；`lib/providers/discover_provider.dart:163`、`:167`、`:390`、`:559`、`:571`（上述核查快照）。具体插桩点须在实施前复核。

| 指标 | 起点 / 终点定义 | 目的 |
| --- | --- | --- |
| TTID | 系统启动请求 → Activity 首帧，由同一系统工具取值 | 只比较可见壳层；单列 process-cold 与 task-warm |
| 首非空内容 | 本次首页加载起点 → 第一批非空媒体模型提交且卡片可操作 | 排除 itemCount=0 的 ready |
| 首海报 | 同一起点 → 第一张可视区媒体海报完成绘制 | 不把占位图、下载结束当作绘制完成 |
| 完整首页 | 同一起点 → 本次启用的首屏区块进入成功/失败终态且可视海报绘制完成 | 单列是否有失败、是否为旧缓存；不要求屏外图片全载入 |
| 后台更新 | 身份授权就绪 → 首个新数据区块提交 / 全部启用区块终态 | 对比缓存回显后更新；与壳层启动分开 |

**验收：** 同设备、同服务端、同账户权限、同库规模、同网络，进程冷但磁盘温 / 清测试缓存 / 暖返三组各至少 5 次；保留每次记录、范围和中位数。尾延迟判断需增加样本，不能用 5 次样本作稳定 P95 结论。分别统计请求数、在途峰值、重复请求、取消后落地数量、错误率、内存峰值和首屏图片传输量。达标阈值先为 `unset`，基线测量后确定 `TODO(PERF-01)`。

**预期与边界：** 建立可靠归因，尚未产生已证实的速度收益。原型入口：[首页](home.html)外部“启动演示”工具仅展示状态顺序；工具中的时间均非实测。

## 3. P1：去掉首屏中的可拆分等待

### PERF-02 · 同服按库发布，快库不等慢库

**问题与证据：** `lib/services/data_aggregation_service.dart:788`、`:849` 的核查结果显示 Latest 使用滑窗并发 3，但等待全部 worker 完成后才返回。同服里一个慢库可能延后其他库的展示；跨服已有渐进发布。

**方案：** 在既有聚合层追加“库级结果/状态”事件，按固定 section key 更新每行；首个可用库先发布，其余异步补齐。保持库顺序和焦点，不让完成顺序决定卡片位置。启用库集合改变时使用 generation / session epoch 丢弃迟到结果。

**验收：** 注入一个迟缓或失败库，其他库在各自完成后独立出现；错误只落到对应行，可单独重试；不重复插入同名库；切服或切号后旧任务不得提交。比较首非空内容和首海报，完整首页可能不变。实际预算与数值目标 `unset`，`TODO(PERF-02)`。

**风险 / 依赖：** provider 通知粒度、跨库去重、稳定排序、隐藏库过滤必须一致，避免频繁 rebuild。**原型映射：** 首页“首次加载 / 慢库 / 部分失败”展示该交互意图，未改聚合层。

### PERF-03 · 继续观看先可用，剧集与 Logo 后补

**问题与证据：** Jellyfin Continue 在 Resume / NextUp 后仍等待 LastPlayed 补全；核查范围包括最多 24 系列、并发 4、单项 3 秒、整 pass 4 秒。Plex 首排等待合并 owner metadata 以补 Logo。这些是当前代码观察，不是本轮建议的新默认值。

**代码定位：** `lib/services/jellyfin_client/parts/browse.dart:1758`、`:1807`、`:1824`、`:2305`、`:2609`；`lib/services/plex_client.dart:1677`、`:1689`，均在 `<local-path-withheld>` 下的核查快照。

**方案：** 首批 Resume / NextUp 数据一旦满足可操作条件就提交；LastPlayed 扩展与 Logo 请求后台补全，采用 item key 就地合并。评分、标题 Logo 不作为打开详情的门槛。保留当前必要的业务排序与去重，补全不重置已聚焦项。

**验收：** 延迟或拒绝装饰请求时，卡片仍能进入详情；迟到更新不重复、不抢焦点、不回滚进度；主数据错误与装饰缺失独立表示。测量“首个可操作卡片”变化及后台额外请求数。预期减少首屏门控，收益未测。**原型映射：** 首页延迟评分演示；真实 NextUp / Logo 调度尚未实现，`TODO(PERF-03)`。

### PERF-04 · Views 与重复请求使用同一入口

**问题与证据：** 当前 Views 存在 inflight 合并，但隐藏库分支可能绕过统一入口。不要把“已有去重”写成“完全没有”。核查代码为 `lib/services/data_aggregation_service.dart:160`、`:664` 与 `lib/services/jellyfin_client/parts/browse.dart:323` 相关调用链；精确修改点须按当前源码复核。

**方案：** 统一库列表的请求入口，single-flight key 至少包含服务器、用户授权上下文、过滤条件和请求用途。一次任务的多个订阅者共享结果；取消某个订阅者不应误取消其他仍使用结果的消费者。缓存失效与请求去重分别建模。

**验收：** 同时进入首页、隐藏库设置和返回首页，仅同 key 的在途请求合并；不同账号/权限/过滤不得复用。统计合并前后实际 HTTP 数、合并命中与失败重试行为。不要预设 TTL，`TODO(PERF-04)`。**原型映射：** 无真实去重演示；属于生产实施建议。

## 4. P2：首页缓存、图片和请求预算

### PERF-05 · 身份权限确认后，安全地先显旧内容

**现状：** `lib/services/home_snapshot_store.dart:64`、`:69` 与 discover provider 的核查结果表明已有 24 小时快照和 scope/epoch 防护，但读取受 online 客户端条件限制。`read(HomeSnapshotScope scope, {required bool Function() isCurrent})` 是已有接口，不能删掉有效性检查以换取表面速度。

**方案：** 先复核授权身份、profile / PIN 与隐藏库策略，再评估是否可在健康检查完成前读取同 scope 快照；以旧内容可浏览、后台刷新表现更新。logout、撤权、切号立即使 scope 失效。若无法保证权限，保留现有门槛。离线详情/播放是否可用另作能力判定。

**验收：** PIN 未解锁、换账号、撤权、隐藏库、scope 过期均不得泄漏旧卡片；同 scope 刷新失败保留可用内容并允许重试，明确旧内容状态；后台成功只更新对应行。衡量授权就绪至缓存首显时间，不能与未授权壳层相比。**原型映射：** “缓存回显”是已授权样例，不实现真实鉴权；快照策略新默认 `unset`，`TODO(PERF-05)`。

### PERF-06 · 按源预算、局部超时和取消

**问题：** 继续增加全局并发可能抢占身份、首屏图片和其他服务器；离开页面后迟到任务可能覆盖新会话。VidHub 的 5 次方法调用集中发起不等于最佳并发为 5。

**方案：** 按服务器设置共享请求队列，区分关键主数据、当前可见图片与屏外补全；复用身份就绪后的现有 2 秒内容预算，不将其冒充整个启动时限。为单库设置独立可取消任务，结合会话 generation 检查与真实 HTTP 取消；单项失败不触发全屏失败。评估并发 3 / 5 / 6 仅作为实验候选，不直接升到 6。

**代码定位：** `lib/main.dart:1263`、`:2276`、`lib/services/data_aggregation_service.dart:788`、`:849`；取消传播还需实施前专项核查。**验收：** 慢源不饿死快源；切服后旧结果提交数为 0；测量首图、错误率、在途峰值、队列等待与 CPU / 内存，找到拐点再设值。新并发上限、超时、重试退避参数均 `unset`，`TODO(PERF-06)`。**原型映射：** 慢库/失败/场景切换只模拟可见效果，不验证 HTTP 取消。

### PERF-07 · 按可见尺寸取图，固定占位，限制屏外加载

**方案：** 按卡片逻辑尺寸 × 设备像素比请求匹配图片；首屏 hero / 首行优先，屏外卡片按需加载；固定宽高比防止加载导致布局移动，滚动接近时有限预取；对解码缓存与磁盘图片缓存分别观测。不要将图片缓存与播放缓冲混用。

**证据边界：** 用户截图支持海报主导与横向卡片布局，不能证明 VidHub 图片缓存参数；本轮没有当前 Flutter 图片链的逐行定位。现有 HTML 的 `theme.js` 32×32 取色与 560 ms 过渡是自主原型行为，也不是竞品性能算法。

**验收：** 同屏视觉质量不下降，卡片尺寸稳定，屏外请求受控；比较首图、传输字节、解码峰值与滚动帧耗时；深浅主题下占位可辨认。生产图片链定位、缓存容量、预取距离待 `TODO(PERF-07)`；**原型映射：** 行级骨架与卡片尺寸可评审，真实图片优化未实现。

### PERF-08 · 评分随主响应，来源缺失不追加猜测请求

**事实：** J/E 的 `CommunityRating` 映射 audience（0–10），`CriticRating / 10` 映射 RT critic，但无法仅凭字段名还原服务端抓取来源。Plex 使用 `ratingImage`、`audienceRatingImage`、`Rating[]` URI 判断提供方。Simkl 一次详情可带多个站点评分，因此多品牌不等于多次 HTTP 请求。以上为 Velo 核查结果，非 VidHub 网络归因。

**方案：** 优先消费首页/详情主响应已有评分；将数值、尺度、来源标识、取得时间和是否演示分开。无来源用中性评分图标，说明弹窗与无障碍标签显示“评分 / 来源未标注”，缺分不显示 0.0；只有产品明确需要且用户配置允许时再做外部补全，独立缓存、去重和限流，不阻塞卡片。

**请求模板（只用于实施定位）：** J/E `<local-path-withheld>`；Plex `/library/metadata/{ratingKey}`（外部 ID 可使用 `includeGuids=1`）；Simkl `/{type.detailPath}/{simklId}`。不包含真实账号、作品 ID 或服务器地址。

**验收：** 主响应已有评分时不无故增加第三方请求；同值不同来源不混为一项；10 分制与百分比明确；来源不明保持泛称；缺分与真 0 分按服务端语义区分。提供方授权/接口与评分 TTL 未确认，`TODO(PERF-08)`。**原型映射：** 首页与详情评分说明、本地后补演示。VidHub 首页星分具体提供方仍未知；详情紫标只支持图标对应推断，不证明实际分数来自 Trakt HTTP。

### PERF-09 · 播放优化保留后级，不挡首页交付

缓存到磁盘、容量/时长、硬解、音频硬解、DV、去隔行、PiP 有资源线索；“512 MB”仅为资源展示文本，不能写成已验证默认值。一次 externalURL 日志自报 `hwdec=auto-unsafe`、`vo=gpu`、MPV legacy_routing，仅限该实验路径，不证明手机实际硬解或通用默认。`probesize=262144`、`analyzeduration=1000000`、`fflags=nobuffer`、AVIO 64 KiB 是探测路径参数，不是播放缓冲。

**方案 / 验收：** 保留 mpv / ExoPlayer，VLC 保持可选计划；后续在真机以 API 读回、解码器实际命中、丢帧和功耗验证，不把模拟器 codec 当真机证明。当前优先首页，真实参数/收益均未测，值为 `unset / 跟随核心`，`TODO(PERF-09)`。**原型映射：** 网络与缓存、播放设置只作分区与未设置状态说明。
