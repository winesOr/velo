# VidHub 缓存、硬解与最快线路：可证伪验证计划

范围：VidHub 3.0.3 / 318，用户提供base+arm64样本；目标是区分“设置UI值”“业务实际传参”“内核运行状态”“网络行为”“性能结果”。本文件是试验设计，不是执行记录或结果。依据已有两份静态/GUI简报与native简报；不重读APK。现有已知：双View/双库、512MB展示资源、缓存分钟格式、最快线路资源、JNI通用mpv选项桥与Surface生命周期。未知：实际偏好默认、档位映射、策略实现、运行硬解和最快算法。

## 1. 动态就绪门槛

| 门槛 | 必须记录的证据 | 不满足时结论 |
| --- | --- | --- |
| Android可用且授权 | 设备/模拟器型号、ABI、系统、ADB连接状态，用户授权范围 | 停在静态；无设备不编运行数据 |
| 样本可运行 | 已安装包版本与输入SHA256关联；如需安装确认匹配density split | 缺split/签名或ABI不符，不强行拼装/换包 |
| 受控媒体能播放 | 无账户本地HTTP地址、媒体哈希、音视频编码、设备可达性 | 不借用私人媒体服务/不尝试带token链接 |
| 观测路径可用 | 应用自身诊断、现有调试/插桩权限、系统日志或只读性能接口 | 正式包不可调试时，API实参保持未知 |
| 网络条件可重复 | 服务端单调时钟、可配置延迟/失败行为、响应日志 | 无法控制网络时只写观察，不能判定算法 |

不得为取证root设备、关闭SELinux/证书验证、重签/注入生产App或扩大设备权限。需要额外权限的路线停下报告；不把静态工具完成当动态就绪。已有可用的授权插桩能力可以用，但需记录来源与限制。

## 2. 无私有数据的测试夹具

在用户机器上运行只绑定回环地址的无鉴权HTTP服务；Android经已授权ADB反向端口映射访问同一服务（若可用），否则只在既有授权网络路径测试。使用新生成或明确授权的短片；不读取用户媒体库。

媒体清单记录SHA256、大小、时长、封装、视频codec/profile/level、分辨率、帧率、音频及字幕。至少准备一个易解码片源作为连通对照，再按设备能力准备HEVC/高码率/ASS片源。若工具链或授权素材不足，直接列缺口，不从私人服务下载。

HTTP服务实现HEAD、GET、Range/206及Content-Range，固定ETag/Last-Modified、Content-Length；日志记录单调时间、route ID、请求ID、method、脱敏路径、Range、状态、响应字节、TTFB、完成/断开。避免写Cookie/Authorization/完整URI查询串。

三条路线返回字节完全一致的媒体或受控媒体服务数据：A低TTFB/B高TTFB/C可控失败。延迟、限速、错误和断连在服务端逐路线注入；不修改操作系统全局网络/安全设置。路线页面若只支持完整媒体服务地址而非任意HTTP流，必须使用明确兼容且本地隔离的测试服务；直接文件播放只能检验HTTP行为，不能替代“最快服务器线路”实验。

## 3. 事件与证据格式

每次运行分配run_id，记录monotonic_ns与wall_time、工具/设备、App版本、核心选择、操作、原始UI值、请求序号和来源。跨主机时钟不直接相减：先测量同步误差/采用同一侧时钟，无法对齐只报告各侧先后。

| 层级 | 最低观测字段 | 能证明什么 |
| --- | --- | --- |
| UI/偏好 | 控件标签、当前值、修改动作、重启后值；截图或可读UI树 | 用户选择及持久化表现，不是内核实参 |
| JNI桥 | MPVLib入口、线程、时间、name/value、返回码；调用与init/load先后 | 应用提交给桥的确切输入 |
| Native API | mpv_set_option_string/mpv_set_option/mpv_set_property名称、格式、值、返回码、mpv实例标识 | 参数到达内核API，仍需看结果 |
| 播放生命周期 | mpv_create/initialize、loadfile或等价、start-file/file-loaded/video-reconfig、停止销毁 | 配置生效阶段及会话边界 |
| 运行属性 | hardware-decoding对应实际属性/日志、解码器名称、帧/缓冲状态 | 实际运行路径，非设置开关 |
| 网络 | 请求开始/取消/首字节/结束、路线和响应状态 | 实际探测/播放/重试和选择时序 |
| 系统 | PSS/CPU/帧时间/温控等采样口径 | 测量指标，不能单凭CPU低断言硬解 |

插桩条件满足时，先观察JNI MPVLib_setOptionString，再观察mpv_set_option_string、mpv_set_option、mpv_set_property，以及初始化/加载入口。记真实name与value，不预设出现cache/hwdec。set_option/property的data是按mpv_format解释的指针；只能按经核实ABI安全解码，未知format保留格式和地址，不猜值，不盲读内存。字符串仅保留非敏感选项；媒体路径/鉴权头不写入报告。

前轮已确认g_mpv共享存储与通用桥；这些ELF地址不是运行地址。若采用地址定位需保存库SHA256、加载基址和重定位计算，不把静态地址直接当运行地址。VLC可能被选用，mpv无调用只说明本次观测未见，不证明设置失效；需记录实际核心并切换到其相应可用诊断。

## 4. 缓存试验矩阵

| 编号 | 单变量操作 | 应记录 | 可证伪判定 |
| --- | --- | --- | --- |
| C0 | 首次可观察设置，不重置用户数据 | UI当前值、可观察偏好来源、冷/热状态 | 只有资源文本不能称首次默认；既有配置不能称出厂默认 |
| C1 | 磁盘缓存关闭→开启；其他条件固定 | JNI/API name/value/返回码、设置相对init时序、文件增长、HTTP字节 | 无调用或仅UI变化时，不能写内核启用 |
| C2 | 容量逐个可见档位选择 | 每档UI文本、实际参数字节/单位、重启后值 | 只有观察到完整对应关系才称档位映射；不补齐未选档 |
| C3 | 时长逐个可见选项选择 | 分钟UI值、实际API名/值及单位 | 不能从min资源推断内部值为分钟/秒 |
| C4 | 小容量+长时长 / 大容量+短时长交叉 | 到达阈值时文件/缓冲/请求行为 | 仅有AND/OR提示文案不足；反复条件需支持哪个门槛终止 |
| C5 | 同片冷/热复播、seek到未缓存段 | 缓存文件增量、请求Range、重复字节、取消旧请求、seek完成事件 | 网络字节减少可能来自系统/HTTP缓存，需区分层级 |
| C6 | 切集/退出/重启 | 缓存保留/清理、实例/线程/文件释放 | 不将短观测无增长等同于不存在泄漏 |

实际磁盘位置只有在现有授权可读时检查，沙箱不可读不能强闯。缓存窗口未达阈值时不能宣布实现不存在。资源描述512MB或XML slider初值3均不能直接填C0/C2结果。

## 5. 硬解与Surface试验矩阵

| 编号 | 操作 | 应记录 | 成功/失败标准 |
| --- | --- | --- | --- |
| H0 | 固定片源和实际核心，读取运行解码状态 | App/内核暴露的hwdec-current或等价实际属性、解码器名称、软件回退日志 | 属性名/语义由当前内核确认；若只有开关，运行硬解未知 |
| H1 | 硬件加速关闭→开启 | API实参、返回码、重建/重载时序、实际硬解状态 | 开关开启但回退软件时必须报告回退；不得称硬解命中 |
| H2 | AVC/HEVC以及设备明确支持的profile对照 | 同设置下的真实解码器/输出模式 | 格式不支持不能推断App策略普遍失效 |
| H3 | 视频硬解与音频硬解分开切换 | 各自的decoder/API参数、音画时间戳 | 音频硬解选项不代表视频硬解；系统codec存在不等于在用 |
| H4 | attach/detach、旋转/PiP/后台恢复 | Surface全局引用创建/删除、mpv选项名/值、播放器事件 | 实际生命周期调用序列才可验证释放；静态destroy职责分离不等于泄漏 |

CPU/功耗/掉帧只作对照结果，不作为唯一硬解判据。杜比视界只在可用合法测试片和支持设备上试；否则保持未知。不能用模拟器的软件渲染结果推断手机硬解表现。

## 6. 最快路线可证伪矩阵

| 编号 | 可控变化 | 必须看到的事件 | 能排除的假设 |
| --- | --- | --- | --- |
| R0 | 手动选A/B | 确切播放请求落到目标路线、UI选中、失败 | 验证测试服务真被使用，而非只改UI |
| R1 | A低延迟/B高延迟，然后互换 | 每路探测发起/结束、选择时间、播放请求首个route ID | 若顺序/缓存固定，可排除简单“每次选最低TTFB”的断言 |
| R2 | 低TTFB低带宽 vs 高TTFB高带宽 | 探测payload大小、持续时间、最终选择 | 区分响应延迟与吞吐优先，未覆盖其他特征仍不称完整算法 |
| R3 | 默认/主线路失败或超时 | 探测/播放失败→下一路线请求→UI变化及时间 | 验证失败回退是否存在及触发时点 |
| R4 | 已选路线播放中断连 | 重连、换路、Range续传或从头请求 | 验证播放中回退，不与启动选路混淆 |
| R5 | 关闭重开/刷新路线后重复 | 是否重复探测、缓存选择保留期 | 仅在已测时间窗推断缓存，不能写永久TTL |
| R6 | 相同条件随机轮换地址/次序 | 多次选择分布、并行/串行探测时序 | 区分列表顺序/首成功策略；有限样本不能唯一恢复算法 |

每条件至少5次用于初步复现，报告全部样本与中位数；要报P95等尾部分位需增加样本并披露算法/样本数，不用5次记录冒充稳定尾延迟。每次变更一个因素，记录warm/cold；计时只比较可对齐时钟。即使选择变化支持某种规则，也标“观测一致”，只有实现证据才称算法恢复。

## 7. 交接给报告的最低格式

每条结论：问题ID → 输入与控制变量 → 工具调用/可复核原文 → 稳定本地证据文件与行号 → 观察事实 → 可排除假设 → 剩余未知。原始失败和无结果也保存。没有执行的行标未执行/门槛阻塞，禁止填示意数字当实测。

本轮不得修改正式Flutter/Android或prototype。结果确认后再更新报告，保持资源E、调用E、运行E、机制I和建议P分层。所有服务/媒体为本地测试，日志去除令牌、私人URL、账号信息。没有动态就绪条件时，仍可给出静态可证实部分和上述具体阻塞。
