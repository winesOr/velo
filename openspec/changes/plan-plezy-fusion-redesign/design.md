# Design

## Context

动机与范围见 [proposal.md](proposal.md)，分期和后续独立工程见 [roadmap.md](roadmap.md)。本设计基于本地代码与 2026-10-22 原型，尚未进行应用实现或真机验证。

| 领域 | 已核对的现状 | 改造落点 |
|---|---|---|
| 弹幕状态 | `DanmakuSession` 内存单例，默认 127.0.0.1，仅开关/字号/透明度 | 设置仓储、源模型、会话生命周期 |
| 弹幕请求 | `DanmakuApiClient` 仅 search/episodes + comment，字符串拼接 URL | 端点规范化、三步 API、顺序尝试和请求取消 |
| 热力 | `BufferRangePainter` 仅章节底轨与缓冲；原型 proto.js 有曲线和统计 | 独立纯计算模块 + 现有 painter/slider 扩展 |
| Logo | jellyfin_mappers 已有自身/父级 clearLogoPath；已有 ClearLogoImage | 播放控件接入与指定图片尺寸，避免重复映射 |
| 首页 | 已有 VidHubAmbientBackdrop 和取色器 | 修改 Hero 空间布局和主题共享范围 |
| 主导航 | NavigationTabId 尚无一起看项，已有多个用户可配置页 | 增加一起看目的地，兼容既有持久化选项 |
| 媒体库 | LibraryQuery、query translator、库标签页已存在 | 组合条件到服务器能力的映射 |
| 一起看 | 房间、时钟同步、房主协调、访客修正、中继端点已有实现 | 页面组织与状态展示，避免重复建同步系统 |

证据冲突处理：

- 最新 `home.html` 为通栏人物海报，优先于早期分析的悬浮卡设计；沿用已有取色和玻璃基础。
- `cast-preview.png` 仍显示首页投屏按钮，最新 HTML 已改为播放器入口；以 HTML 为准。
- `proto.js` 为主轨上方曲线、共享画布；采用该形态，替代早期方案的轨道背景染色候选。保留生产 3/8dp 主轨，原型 5/6px 不覆盖已实现交互契约。
- `reference/` 的“不引入 VLC”“Yamby 热力实现不可读”等旧结论已被 `CLAUDE.md` 更新。本项目算法仍为自主设计；可选 VLC 放后续独立 change。
- `settings.html` 的“其余用 mpv”与默认双核策略不一致，采用平台原有默认；原型 wss 中继示例改用现有 HTTP(S) 基址语义。

## Goals / Non-Goals

**Goals:** 一套业务状态支撑手机和 TV；按规格提供真实数据、错误/空态、焦点与持久化；阶段间可独立回归和回退。

**Non-Goals:** 本 change 不建设文件索引、网盘鉴权、DLNA/Cast 协议或 VLC 后端，不复制原型静态数据，不修改只读证据和第三方资源。桌面保留响应式导航与键鼠可用性，暂不另外设计桌面视觉稿。

## Decisions

### 1. 持久设置与播放会话分离

在既有 SettingsService 上增加带版本的弹幕设置仓储；DanmakuSession 只维护当前条目、加载状态和有效数据，并订阅设置。继续使用 Provider/ChangeNotifier，避免为了新界面引入第二套状态框架。

拟新增 `lib/danmaku/danmaku_settings.dart`、`danmaku_source.dart`、`danmaku_settings_repository.dart`；按现有存储规范复用 SharedPreferences。源含稳定 ID、名称、地址、顺序、启用状态；连通延迟与错误为临时状态，不持久化过期成功结果。保存失败不得报告成功。API 凭据遵循现有安全存储机制，禁止进入一般设置导出或日志，源地址中的 token 同样脱敏。

匹配记忆键为 profile + serverId + seriesId + seasonNumber，值含 sourceId、animeId、集号偏移与时间偏移；单片以自身 itemId 隔离。更换源地址或删除源时失效相关匹配。内存中的历史默认地址不迁移为用户配置。

### 2. 请求和匹配层

端点模型接受 HTTP(S) 基址，去掉尾斜杠，保留路径前缀，对已有 `/api/v2` 尾段避免重复追加。与现有客户端相同，最终请求为 `<prefix>/api/v2/<route>`。拒绝含 query/fragment 的模糊基址并给出修正提示。

三步方法分别获取作品、分集、评论；404/405 等明确路由不支持时才走旧 search/episodes。超时、空候选、解析失败与鉴权错误分别反馈，可尝试下一启用源；候选模糊时等待人工选择。请求携带会话 generation，换集/源/用户后取消或忽略过期响应，失败不让旧影片弹幕留在新影片上。

精确 `https://api.dandanplay.net` origin 才进入官方签名适配器；不使用字符串前缀判定，不把签名跨 origin 重定向。缺自有凭据明确不可直连。签名算法实现前以官方契约和已知样本核验，当前未核验的算法不写死在计划中；自建网关路径可独立交付。

### 3. 一条有效弹幕数据管线

解析并按时间排序 → 关键词过滤/去重 → 应用时间偏移 → 剔除片长外数据 → 共享给 overlay 与热力。密度限流只影响屏幕呈现，不改热力统计。去重的拟定规则为同类型、去首尾空白后相同文本在滚动 1 秒窗口内保留最早一条；保留原始解析列表以便关闭过滤时重新计算。关键词以非正则子串匹配起步，避免暗含不受控表达式成本。

偏移正值表示延后，集号偏移与时间偏移使用独立字段。换片、seek、暂停恢复使用已有播放器时钟；全局样式与按季匹配偏好分开存储。

### 4. 热力算法与绘制

新增 `lib/danmaku/danmaku_heatmap.dart`，返回不可变 bucketMs、counts、displayValues、peakIndices。桶数 ceil(duration/bucketMs)，原型的九桶均值平滑仅用于 displayValues；P95 用未平滑原始 counts 按规格索引取值。复杂度为 O(n + b log b)，桶数量约 600，不能把含排序的完整过程宣称为纯 O(n)。

在原 BufferRangePainter 增加热力、跳过区间和绘制高度参数，先曲线后轨道，复用 segments 裁剪；更新 shouldRepaint。复用 slider 的布局/手势层提供曲线区域，不额外叠加独立热力 Widget 或每帧 saveLayer。播放头仍由现有机制绘制，避免重画或丢失预览。

数据缓存键包含条目、弹幕版本、片长、过滤配置和 offset；播放 position 更新只改变指示位置。有效片长未知时暂不构建热力，片长就绪后更新。

点击热力区的窗口固定为原点击桶 ±6，不能在搜索过程中移动窗口。窗口内最高值平手按距离再按较早索引选择。TV 全局最近峰值使用 displayValues 的正值局部极大，平台连续峰取中点；若没有局部极大但有正值，使用全局最高平台中点。长按确认采用一次性触发且消费后续 key-up，防止额外播放/暂停。长按阈值复用已有输入策略。

### 5. 视觉与导航接入

主题继续用 mono tokens/motion；将首页当前媒体和氛围色作为明确状态共享到背景、渐变和底栏。取色只对低分辨率图运行，沿用缓存，异步结果携带条目身份。减少动态效果时禁用持续动画。真实海报无 Logo 时显示标题，示例截图不打进正式应用。

增加一起看导航标识时检查序列化、启动页、远程切页和快捷键映射；保留旧导航配置的读取与迁移，原有功能移入可达次级入口。TV 顶栏和手机底栏共享目的地，按输入方式和布局切换，全部走 `lib/focus/`。

媒体库复用 LibraryQuery 和 translator。第一版“全部来源”可分来源显示有序分组及各自分页，明确分组计数；如要统一跨服全局排名，必须实现服务端支持或可证明完整的归并游标，不能对已加载页排序冒充全库顺序。来源切换重置游标并使旧请求失效。

### 6. 一起看、播放器与设置

对 `lib/watch_together/screens/watch_together_screen.dart` 做视觉和导航适配，继续使用现有 controller/provider/relay。原型“准备”按钮如协议无对应事件，显示媒体解析/连接状态，不新增虚假 ready 布尔值。房间码和最近房间按真实服务处理。

Logo 接到已有 clearLogoPath/ClearLogoImage，确认请求参数与图片失败回退。跳过撤销只保存当前 item/session 的跳前位置和过期时间，撤销后记录当前片头区间抑制自动重跳；切集清空。

全局与面板共享设置模型，手机底部面板和 TV 分类详情为两个表现层。扫码/手机同步配置需要已鉴权的远程能力，放后续投屏 change 的扩展任务，不以原型文案暗示已实现。

## Risks / Trade-offs

- [原型覆盖未来功能] → 本 change 只交付八项 capability；投屏、文件源和 VLC 独立提案，见 roadmap。
- [canvas_danmaku 对精确行数控制不足] → 核对实际 API；必要时在 overlay 调度层做显式限流和轨道配额，禁止用不准确的面积比例冒充行数。
- [玻璃和热力造成掉帧] → 数据缓存、有限采样、paint 范围隔离；同设备同影片记录改造前后 FrameTiming，实机未完成不能宣称性能过关。
- [不同服务器筛选能力不一致] → 能力感知与明确降级；不静默忽略用户条件。
- [官方凭据或真机缺失] → 自建源测试与模拟 HTTP 可先完成；官方端到端和实机项保持未完成，单独记录阻塞条件。
- [导航改变破坏旧偏好] → 迁移测试覆盖离线、启动页和已有隐藏项，不删除既有存储键。

## Migration Plan

1. P0 按源持久化 → 匹配/偏移 → 热力 → Logo 的顺序落地；每批独立提交与针对性测试。
2. P1a 改导航与首页，再接媒体库、设置、一起看；P1b 完善样式过滤和撤销。阶段顺序见 tasks。
3. 只增加带版本的配置键；存量用户第一次打开弹幕才触发空源引导。回退 UI 提交时新配置可保留，旧客户端忽略未知键。
4. 回滚热力时关闭开关并回退 painter/slider 接入；不影响基本弹幕或播放。回滚匹配时保留本地导入路径。
5. 通过对应单测、analyze、仓库 CI、Android arm64 与 TV 人工验收后才能标记阶段交付；所有 task 完成后才 archive。任何缺失设备/凭据验收保留为未勾选。
