# Design

## Context

动机见 proposal.md。现有播放信息请求与内核准备已并行；详情页已有元数据探测。Android mpv 使用异步串行队列，ExoPlayer 在尚未回退时缓存 mpv 属性。字幕目前作为打开媒体的附带输入，远程读取可能阻塞整个打开流程。

## Goals / Non-Goals

**Goals:** 保留配置完成语义，减少通道往返；复用无副作用的协商结果；使远程字幕下载不阻塞视频并严格隔离播放代际。

**Non-Goals:** 本轮不改显示模式等待、FFmpeg/mpv 探测参数、缓存预算、播放内核或 UI 导航。

## Decisions

1. 批量接口返回逐项错误，普通平台提供顺序回退；Android mpv/ExoPlayer 提供单次通道请求，逐项调用已有处理逻辑并等待回调。仅独立偏好合批，保留 DV、音频和用户配置的既有覆盖顺序。观察注册使用流水发送，在注册全部完成前不发布内核就绪。
2. 无副作用预解析以客户端为边界。Jellyfin/Emby 原画点播可预先协商，按认证会话、当前端点和初始化选项精确匹配；容量和 TTL 有界，失败删除，播放消费一次。Plex 继续复用元数据缓存，不在详情页调用有服务端写入的转码准备。下载检查仍先于缓存消费。
3. 远程字幕先在 Dart 后台下载到播放器私有临时目录，然后把本地 URI 挂载给内核，避免把网络阻塞从 loadfile 移到 sub-add。并发有界，第一次 1.5 秒，失败后台重试一次。离线/本地字幕沿用原路径。
4. 挂载保留原始 URI 和来源 ID 的映射，避免轨道匹配丢失。打开接受前检查尝试，接受后以活动下载器和片源代际为作用域；重载期间等待转场结束，成功后拒绝旧任务，预解析失败仍保留旧视频时允许其字幕继续。退出取消任务，原生释放后删除文件。TrackManager 保存用户晚近音轨/主副字幕选择；字幕到达后仅在没有正在执行的选择或轨道监听时重新准备选择，避免覆盖用户意图或重复 ExoPlayer prepare。
5. mpv 通过 sub-add 挂载本地文件；ExoPlayer 复用原生添加字幕能力，需要激活新字幕时保留当前位置和 playWhenReady 后重新准备。不得将所有远程 URL 直接交给 mpv 或 ExoPlayer 后挂。

## Risks / Trade-offs

- 字幕晚到 → 保留字幕目录和用户意图，异步挂载后重新触发轨道选择，不把临时缺失记为关闭。
- ExoPlayer 新字幕可能触发一次重新缓冲 → 下载已完成后再挂载，且保留位置与暂停意图；回归测试验证不回到零点。
- 缓存结果过期或错误复用 → 小容量、短 TTL、选项和会话隔离、一次消费；失败走正常初始化。
- 原生批次中途退出 → 继续使用现有实例所有权和代际检查，逐项回调后才回复批次。

## Migration Plan

依次实现属性批处理、预解析、字幕后台加载，逐项运行回归后启用。无数据迁移，不新增设置。保留显示匹配与字幕选择策略，文档记录尚未完成的真机性能验收。
