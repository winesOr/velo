## 怎么用

1. 一个会话只做一个任务包。开工前完整读对应任务卡,不需要再读清单和第一轮方案,规格数值已抄进卡里。
2. 按卡里的"提交拆分"逐个提交,一个提交只做一件事,提交信息用中文加类型前缀。
3. 每个提交前通过:`flutter analyze`、`scripts/run_tests.sh`(或卡里指定的测试文件)。
4. 改了 `lib/i18n/*.i18n.json` 后运行 `dart run slang`,不要手改生成的 Dart 文件。
5. 卡里标"待核对"的地方先按卡里给的命令核对,再动手。
6. 卡里标"默认值"的决策可以直接按默认值做,并在完成报告里列出。
7. 需要改卡里没列出的模块或接口时,停下来写进报告,不要自行扩大范围。

## 建议执行顺序

1. **R1** → **R2**(用户明确要求的改动和确定的缺陷)。
2. **R3**(代码很小;真机验收可以和后面的包并行安排)。
3. **R4** → **R5**(界面上最容易看到的收尾)。
4. **R6**;**R7** 先单独做 R7-8 的基线测量,再做其余。
5. **R9** → **R10** → **R11**(依赖顺序固定)。
6. **R8** 穿插进行:R8-1/2/3/5/6 都小,可随时做;R8-4 颜色收敛按目录分批,排在 R1、R10 之后。

可以并行的组合(不改同一文件):R3 与 R4;R6 与 R5;R7 与 R9。不要并行的:R1 与 R2-2、R1 与 R8-4、R4-1 与 R9-10、R5 与 R2-3。

## 对清单的更正

写任务卡时逐个打开代码,发现清单里这些说法不准确,以这里为准:

| 清单说法 | 实际情况 | 影响 |
|---|---|---|
| TV 首页轮播也有播放按钮 | TV 首页走全屏聚光图 `TvSpotlightScaffold`,没有轮播也没有按钮;头图代码里的 TV 分支是死代码 | R1 只改手机、平板、桌面,TV 只做核对 |
| 头图上有下载按钮 | 没有下载按钮;"版本/音频"来自徽标行里的画质标签 | R1 删的是这一行 |
| 没有圆角 token | 已有 8/12/20/5 等,缺 14 和统一入口 | R10-1 是补齐而不是新建 |
| 关于页、外部播放器页在 build 里建 future | 两处已是静态或已记忆化,只有设置页两处是真问题 | R6-6 只改设置页 |
| 直播节目单可能不是懒构建 | 已经是懒构建 | R6-7 不动 |
| 启动链可以整体并行 | 连接列表依赖迁移和清理,不能并行,只能提前发起连通性探测 | R7-1 收益有限 |
| 海报进详情是整页淡入路由 | 走的是详情页自己的路由;整页淡入只用于启动页、登录页等 | R11 改的入口不同 |
| 写死时长约 256 处都要替换 | 真正的界面动画约 55 处,其余是时间换算、超时、防抖和播放器同步 | R11-4 范围大幅缩小 |
| 硬编码颜色约 411 处 | 去掉误匹配约 398 处,其中播放器目录约 162 处属合理保留 | R8-4 实际要改的约一半 |
| 手机遥控页有平铺选择器 | 那些是命令按钮和标签页,不是选择器 | R4 不动 |
| 轨道选择辅助类丢副标题是隐患 | 嵌入分支已确认是死代码 | R4-3 定为删除 |

## 验证欠账

- 第一轮实现的 `flutter analyze` 两次异常退出,不算通过;全量测试和 `ci_checks.sh` 没跑。第二轮开工前先跑一次,把基线结果记下来。
- 第一轮所有真机和 TV 项都没验:30 分钟长播、切轨、遥控与触感、冷启动耗时、帧率与内存。
- 屏幕常亮的"首帧后短暂空闲会释放"是从代码推断的,需要真机日志证实(步骤见 R3)。

## 通用约束

- 保留 Plex、Jellyfin、Emby、一起看、手机与 TV 支持;保留 mpv 与 ExoPlayer 两个后端。
- 用户可见文案走 slang;TV 上可交互控件用 focusable 包装。
- 不提交凭据、签名材料、构建产物、本地参考材料。
- 业务数值未定的做成常量或可注入参数,加默认值和 `TODO(编号)`。
- 每个界面改动在亮色、暗色、纯黑三种主题,以及受影响的手机、平板、桌面、TV 形态下逐一检查。
- 播放器控制层始终深色,不随主题变;播放器帧时序、进度、手势相关的时长不替换。
