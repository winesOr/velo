# VidHub Android 原生界面实际观察 · 2026-11-13

本轮仅观察 **Android VidHub 3.0.3（318）**。来源是既有 `plezy_api36` Android 16 / API 36 arm64 模拟器，显示 720×1600，播放器自动横屏为 1600×720；不是实体手机。两次设备列表均只有 `emulator-5554`。本轮不包含 Mac、SenPlayer、爆米花的原生结论。

操作方式为 REA 启动客户端、ADB `input tap` / 返回键与屏幕截图，是对真实安装应用的输入，不是浏览器原型，也不是物理手指触摸。未测帧率、动效曲线或精确持续时间。设置截图中的数值是当前设备值，**不代表出厂默认值**。

## 播放样片与限制

- 样片由本轮协作者使用现有 Swift/AVFoundation 在 `<local-artifacts>/velo-native-sample/` 生成，纯几何动画；协作者验证为 9 秒、1280×720、H.264、单视频轨、无音轨。该验证是样片验证，不是 VidHub 解码成功证据。
- 仅把 MP4 推到模拟器 `/sdcard/Download/VeloResearch/velo-geometric-test.mp4`，没有导入服务器、私人媒体库或下载远端影片。没有推送外置字幕。
- `file://` 打开报文件不存在；直接构造 content URI 授权被 Android 拒绝，随后改为系统 Files 的实际点击打开。文件存在性和系统授权路径已区分，不能把前一错误归为编解码失败。
- 本次样片在 API 36 模拟器授权打开后出现加载与系统 ANR，**不能泛化为 VidHub 真机性能或所有文件的播放能力结论**。没有通过切引擎、重新编码或安装工具继续排查竞品。

## 对 Velo 的建议（设计提案，非竞品事实）

1. 参数行保留“名称 + 当前值”的清晰结构，进入二级设置后减少一级导航干扰；评分与播放设置都可沿用。
2. 开关、单选当前值和主要确认按钮使用一致的强调色语义。这轮 Android 实际画面支持“绿色承担强调色”的判断，但没有证明用户之前问的某个青绿 HEX 等于 VidHub 官方主题色。
3. 文件访问错误应说明问题并提供可达的退出/重新选择；Velo 可改进恢复路径，不必照抄只有 Confirm 的框。
4. 加载态保留标题与退出入口，避免长期无反馈；自定义错误与 Android 系统无响应必须分开描述。
5. 既定 Velo V4 的无中心控件、侧浮抽屉仍按项目约定执行。本轮观察不构成改成竞品底部居中播放按钮的授权。
