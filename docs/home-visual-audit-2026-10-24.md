# 首页原型对照与本轮修正

基线：`design/prototype/home.html`、`ui.css`、`appearance.css`，390 × 844 手机预览，深浅色各一份。通过本地 HTTP 打开原型，使 canvas 海报采样正常执行；不能用 file URL 下采样失败的中性灰背景作色彩基线。

Flutter 截图使用实际 `DiscoverScreen`、`FusionHomeHero`、`HubSection`、`MediaCard`、`HomeThemeScope` 和导航组件，注入与原型相同的《沙丘：第二部》海报及受控服务器数据。卡片内容、继续观看列表和图片来自测试数据，不代表已连接真实服务器。截图不包含原生状态栏；顶部预留 28px 安全区。测试渲染器使用项目 Noto 字体，衬线角色用同一字体替代，不能据此断言真机的系统字体完全一致。

| 对照发现 | 修正 |
| --- | --- |
| 首页强制暗色，浅色选择不生效 | 删除强制暗色路径；首页底色来自当前海报，导航继续遵守所选外观；不再向海报底色混入浅色主题的白色 |
| 副标题用正文色乘透明度，背景换色后灰度不稳定 | 有海报时按实际底色的对比度选择浅色或深色文字，副文字用主文字的 80% 与底色合成；无海报时继承所选外观 |
| 主片名字号偏小，无 Logo 时仍占固定高度，片名和评分间距过大 | 手机回退标题 45px / w600；无 Logo 时按文字实际高度布局；保留服务器 Logo 并适配浅色背景 |
| 缺少外文片名，评分星与正文同色 | 有原始片名时显示 9px 字距 2.5 的上方文字；星号随实际文字对比度使用 `#ffd15c` 或 `#a97516` |
| 浅色工具栏渐变在海报顶部叠白色 | 海报工具栏改为轻黑色渐变；玻璃按钮在两种外观下均保留白色图标 |
| 轮播指示器过宽、位置偏高，浅色仍为白点 | 选中宽 15px，普通点 6px；指示器随海报底色选择文字前景色，保留大触控区域与轮播交互 |
| 海报与内容像两层，较短渐隐形成横带，下方底色泛白 | 使用当前页面同一底色做长渐变：海报高度 28% 开始，98% 完成；透明度按缓入缓出曲线增加，不叠白色或浅灰遮罩 |
| 渐变颜色已一致，接缝仍出现单像素暗线 | 主视觉高度向上对齐物理像素，避免裁剪边界落在小数像素上 |
| 栏目“全部”链接被 Flexible 与 Spacer 挤在中间 | 右侧对齐；继续观看保留真实的全部列表入口 |
| 继续观看的条形进度不符合原型 | 改为内缩白色圆角进度条、右侧真实时间和中央播放圆环；未知时长不显示虚构数据 |
| 最近添加海报偏宽，缺少评分与来源提示 | 手机海报画面宽 105px；使用真实评分、后端标识、年份和类型；无评分不编造 |
| 卡片字重、行距与栏目留白混杂 | 栏目 18px / w600，继续观看标题 13px / w500，普通海报标题 12px；副标题分别 11px / 10px |
| 向下滚动后工具栏一直压在内容上 | 手机工具栏随主视觉滚动；无主视觉、桌面和 TV 保留各自的导航方式 |
| 底部浮动导航距离边缘偏近 | 调整普通手机的最小底部留白，并继续遵守系统安全区 |

## 2026-10-24 长渐变修订

按用户最新要求，允许使用下方底色做更长的融合。`FusionHomeHero` 的渐变与页面共用 `HomeThemeScope` 当前颜色，换海报时同步变色；浅色外观不会把底色稀释成粉白。过渡覆盖主视觉下方约七成，在图片结束前已经达到页面底色，避免短距离内突然变色。取色继续来自海报，不固定成参考截图的红色。

像素回归覆盖黑色海报接深红底色、白色海报接深红底色、同色海报与页面；检查渐变跨度、相邻行变化和接缝一致性，包含深浅两种外观。完整首页截图另外检查了小数尺寸产生的暗线。这些参数是本项目的视觉实现，不代表已经验证了 VidHub 的具体算法。

本次验证：完整首页、主视觉融合、取色、首页主题、主题样式和导航共 55 项测试通过；8 个相关实现与测试文件的静态检查通过，差异空白检查通过。深浅色截图中，接缝上下连续 20 行的采样点均为当前页面底色 `RGB(91,31,15)`；这是《沙丘》测试海报的取色结果，不是固定配色。本次未打包。

## 2026-10-24 详情页复核与同步

复核时详情页仍使用 35%–88% 的线性过渡。本次将首页与详情页统一调用 `MonoPresentation.artworkBlend`，使用同一条 28%–98% 的长缓变曲线；状态栏轻黑遮罩单独处理。详情页画布高度也对齐物理像素，防止相同底色之间仍产生细暗线。

同时发现详情页有了深色海报底色后，浅色外观仍使用深色文字和裸露的深色操作图标。首页与详情页现在共用 `artworkTextColors` 的对比度计算，详情页只适配文字、图标和标题阴影，不套用首页的字号、行高等布局样式；所选外观的亮度保持不变。

新增真实 `MediaDetailScreen` 的海报测试：将《沙丘》原型海报注入图片缓存，验证深浅外观、文字与收藏/已看按钮对比度、共享渐变和接缝上下 9 行的颜色。预览使用测试媒体数据，不代表真实服务器状态：[浅色外观](fixtures/detail-artwork-light.png)、[深色外观](fixtures/detail-artwork-dark.png)。

最终集中回归覆盖详情页、首页、主视觉融合、主题、首页主题及海报取色，共 **126 项通过**；7 个本轮相关实现与测试文件静态检查无问题，相关差异空白检查通过。重新生成并复核了中文详情页截图。这是本轮相关范围的结果，不代表重新执行并通过全仓库 CI。

## 保留的差异与验证边界

- 原型第二个导航叫“搜索”，应用继续保留已确定的“媒体库”主入口；首页右上角的搜索入口仍保留。
- 原型的示例海报、书法片名、独立推荐列表与实际服务器数据不同。应用优先采用服务器 Logo，缺少 Logo 时使用普通片名；没有把示例内容或书法样式写死。
- TV 保留遥控焦点和适合观看距离的尺寸；本轮检查包含 TV 栏目与相关回归，未把手机截图验收声明为 TV 完整视觉验收。
